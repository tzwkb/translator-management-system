## 二、架构变化

### 引入前

```text
启动 FastAPI
  ├─ Base.metadata.create_all()
  ├─ ensure_schema()
  └─ seed()
```

问题：应用启动时会静默改表，数据库没有独立版本号，无法准确判断某次结构变更是否执行过。

### 引入后

```text
手工执行 alembic upgrade head
  ├─ 读取 alembic_version
  ├─ 按版本顺序执行尚未执行的迁移
  └─ 成功后启动 FastAPI
       └─ seed() 仅处理空库示例数据
```

结构变更现在是可追踪的版本文件，应用启动不再承担改表责任。

## 三、实现内容

### 1. Alembic 配置

- `backend/alembic.ini`：配置迁移目录、日志和默认连接。
- `backend/migrations/env.py`：从 `DB_URL` 读取数据库地址，加载 SQLAlchemy 模型元数据，开启 SQLite batch 迁移支持。
- `backend/migrations/script.py.mako`：后续迁移文件模板。
- `backend/migrations/versions/20260717_0001_initial_schema.py`：初始结构迁移。

### 2. 模型元数据

`backend/app/models.py` 正式声明：

- `ux_pending_actor_idempotency`：同一操作人的非空幂等键唯一。
- `ux_pending_active_fingerprint`：活动待审状态下的业务指纹唯一。

两个 SQLite 条件唯一索引不再只存在于手工 SQL 中。

### 3. 应用启动

`backend/app/main.py` 已移除：

- `Base.metadata.create_all(engine)`
- `ensure_schema()`

`seed()` 移入 FastAPI lifespan，仅在应用启动阶段写入空库示例数据。数据库未迁移时，应用会明确启动失败，不会自动建表。

### 4. 旧库基线接管

`backend/app/db_baseline.py` 提供显式接管命令：

```bash
cd backend
DB_URL=sqlite:////absolute/path/to/database.db \
  .venv/bin/python -m app.db_baseline --backup-confirmed
```

安全逻辑：

1. 未传 `--backup-confirmed` 时拒绝执行。
2. 数据库已有 `alembic_version` 时拒绝重复接管。
3. 缺少普通业务表或存在未知表时拒绝接管。
4. 仅允许补齐已知历史缺失表 `pending_idempotency`。
5. 显式执行历史字段补充、数据回填、重复数据处理和索引补齐。
6. 通过 Alembic `compare_metadata` 比对当前模型；存在差异时拒绝打基线。
7. 完全一致时才记录 `20260717_0001`。

## 六、日常使用

### 启动现有开发库

```bash
cd "/Users/spellbook/Desktop/Langlobal/译员管理系统/backend"
.venv/bin/python -m alembic -c alembic.ini upgrade head
./run.sh
```

### 修改数据库结构

```bash
cd backend
.venv/bin/python -m alembic -c alembic.ini revision --autogenerate -m "变更说明"
.venv/bin/python -m alembic -c alembic.ini check
.venv/bin/python -m alembic -c alembic.ini upgrade head
```

自动生成后必须人工审查表、字段、索引、数据转换和 `downgrade()`。模型、迁移文件、业务代码和测试用例应一起提交。

## 七、回滚与恢复

- 代码问题且数据库仍兼容：回退代码，不执行数据库降级。
- 结构变更可安全撤销：停服务、备份当前库，再经人工确认执行指定 `downgrade`。
- 已删除、转换或损坏数据：优先恢复部署前 SQLite 备份。
- `alembic downgrade` 不是备份替代品。
