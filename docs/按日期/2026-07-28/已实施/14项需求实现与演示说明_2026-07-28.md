本文用于回答资源端提出的 14 项需求中“哪些已经完成”，并给出可复核的代码、接口、页面和测试证据。

- 完整实现：5 条（#1、#2、#4、#11、#13）。
- 部分实现：4 条（#6、#7、#9、#10）。
- 未按需求实现：5 条（#3、#5、#8、#12、#14）。

状态定义：

- 完整实现：核心数据、后端、前端操作和校验均可用。
- 部分实现：已有可复用底座或部分流程，但仍缺前端、完整业务规则或真实数据适配。
- 未按需求实现：现有近似功能不能满足该项要求，不能作为交付。

## 四、手动启动与操作

支持平台：当前项目已在 macOS 本地环境验证；后端为 FastAPI，数据存储为 SQLite，前端由后端直接提供。

```bash
cd "/Users/spellbook/Desktop/Langlobal/译员管理系统/backend"
.venv/bin/python -m alembic -c alembic.ini upgrade head
./run.sh
```

浏览器打开 `http://127.0.0.1:8000/`。页面默认使用“资源端”角色加载，可切换只读或 Agent 视角。

主要输入：

- 译员数据：页面录入或 Excel 导入；姓名、母语、入库日期必填。
- 项目经历：先保存译员，再从详情的“项目经历”维护当前/过往项目。
- 标准 PO：`.xlsx`；首行为表头，需包含译员、结算月等字段。
- 语言对：必须从固定代码中同时选择源语言和目标语言。

主要输出：

- 页面中的译员、PO、统计、详情和审计信息：仅页面显示。
- 译员导出：浏览器下载 `translators.xlsx`，包含译员主表和“项目经历”工作表。
- 演示视频：项目 `output/playwright/` 下的 MP4 文件。

## 七、常见问题与恢复

- 旧数据升级后看不到项目经历：先执行 Alembic `upgrade head`；迁移会把旧当前项目转成项目经历。
- 项目经历不能在“编辑译员”中修改：项目已统一移到译员详情的“项目经历”入口，避免旧单值字段与多行台账冲突。
- 实际日报 PO 导入结果为 0 或大量错误：当前导入器只支持标准首行表头 Excel，不应反复人工重试真实 Projectlist。
- 语言代码被拒绝：必须使用固定列表中的代码，且源语言和目标语言不能相同。
- 所有演示视频均不污染开发数据：演示使用独立 SQLite 数据库和独立端口。
- 启动提示缺表：先在 `backend/` 执行 Alembic `upgrade head`，再启动服务。
