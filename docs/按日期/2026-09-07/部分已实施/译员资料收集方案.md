# 译员资料收集方案

2026-09-07

建议同时保留两种入口：现有资料用 Excel 批量导入，新译员及后续资料更新用自填链接。模板减少逐个建档的操作；自填链接把资料录入交给译员，资源端集中审核。

## 已交付：标准导入模板

[译员导入模板.xlsx](../../../../backend/app/templates/translator_import_template.xlsx) 包含“译员导入”“项目经历”“名称映射”“填写说明”四页，前三页为空白数据表，示例仅位于说明页。

主表必填姓名、母语、入库日期、性别，其余资料可后补。建议填写邮箱，便于去重和关联附表。新增时译员ID留空。更新已有资料应先从系统导出，修改并保留ID；模板中的空白列可能清空旧值。

本地系统首页已增加“下载导入模板”，实际下载文件与交付文件一致。更新应用后可从系统取得模板。导入接口会优先识别“译员导入”或“译员”工作表，避免在说明页保存后误读主表。

模板移除了旧版的默认费率、是否双休、档期及自动评级输入。费率继续在系统中按语言对维护，支付账户及附件使用现有专门入口。现有 6 月模板保留为历史文件，请使用新版。

## 本地已实现：译员自填链接

状态：邀请、公开表单、审核入库已开发并通过本地验收，公网地址尚未部署。操作步骤见 [使用说明](../已实施/译员自填链接使用说明.md)。

资源端创建邀请 → 译员打开手机或电脑表单 → 提交申请 → 资源端核对差异 → 确认后入库。

每人一条邀请链接，绑定邀请邮箱；更新资料的邀请同时绑定已有译员ID。译员无需管理后台账号，链接只允许读写该邀请的申请。默认有效期 14 天，资源端可以撤销或重新邀请。

表单分三段：基础信息、专业能力、项目经历。页面提供中英文标签和字段校验。

| 内容 | 译员填写 | 系统处理 |
|---|---|---|
| 基础资料 | 姓名、邮箱、母语、性别、个人/供应商类型；微信、所在地、时区选填 | 核对邀请邮箱；符合当前主表字段规则 |
| 专业能力 | 可承接语言对、领域、文本类型、CAT 工具、日产能 | 语言对可添加多条，限制为系统语言代码 |
| 合作报价 | 按语言对分别填写翻译、审校、MTPE、LQA、LQE 报价及币种 | 显示计价单位，作为待确认报价；资源端确认后才能写入正式费率 |
| 项目经历 | 项目名称、角色、语言对、起止时间；当前项目可填剩余量和截止日期 | 多行录入；资料齐全后按现有项目经历规则校验 |
| 内部管理资料 | 无需译员填写 | 入库日期、来源、状态、试译结果、人工评级、合同及结算策略由资源端维护 |
| 收款账户及证件 | 首版不在基础资料表单收集 | 合作确认后走独立的受限流程 |

未提交可在当前页面继续编辑，但尚不保存云端草稿；提交后展示回执。资源端能查看“待审核、需补充、已入库、已拒绝”，逐项查看新旧差异。退回补充后，原链接会恢复已提交内容和处理意见。更新已有译员时，未提供的字段保持原值；清空旧字段需在管理端操作。项目经历仅新增，完全相同的记录跳过；旧经历的修订或删除在管理端完成。审核拒绝或尚未审核时，正式译员库保持原值。

新申请按规范化邮箱提示潜在重复；与已有记录冲突时由资源端选择合并或拒绝，不自动覆盖。审核入库使用事务及幂等约束，重复提交或重复点击审核不重复建档。通知和邀请链接由资源端自行发送。

## 上线条件与实现位置

当前代码的登录接口可按角色名称直接取得权限，译员列表和导出等读取接口也未统一要求登录。这是现有 Demo 的实际边界，因此自填链接应使用独立的公开收集服务和受限接口，管理后台维持内网访问；如果采用同一服务，则先补齐后台登录与读取权限，再开放公网。

已增加独立的邀请记录和申请记录，保存令牌摘要、有效期、目标译员、提交资料、审核意见及处理人。公开入口 `app.intake_public:app` 只提供表单和申请接口，不提供后台登录、主表、导出或内部管理接口。两个进程共享 SQLite 文件，因此属于接口隔离，并非数据库权限的物理隔离。令牌只保留摘要；原令牌位于邀请链接片段，通过请求头提交，不进入普通访问日志的 URL。

公开入口限制请求体为 128 KiB，按进程/IP 每分钟限制 120 次请求。资源端在后台确认后，调用现有译员、语言对及项目经历逻辑事务入库。报价需单独勾选确认；新建档案的初始状态、入库日期、结算方式由审核人确定。

专项验收覆盖新建申请、补充资料、更新原记录、重复邮箱、过期或撤销链接、并发重复提交、并发重复审核、旧版本/过期差异、越权读取、请求限制。33/33 通过；原有后端 159/159、模板专项 7/7、前端 13 个脚本通过。正式可分发地址需在部署 HTTPS 公开入口并配置 `INTAKE_PUBLIC_BASE_URL` 后生成。
