# 译员资料收集与部署开发文档

日期：2026-09-07\
项目：译员管理系统

## 今日目标

把逐项录入译员资料改成两条可选路径：旧资料继续用标准 Excel 模板批量导入，新译员或资料更新使用邮箱绑定的自填链接。

## 已完成

### 标准导入模板

- 新模板包含“译员导入”“项目经历”“名称映射”“填写说明”四页。
- 导入器优先识别“译员导入”工作表，不受保存时活动页影响。
- 主表必填姓名、母语、入库日期、性别；语言对在系统语言对子表维护。
- 新增中文“人工评级”“人工评级原因”和“CAT 工具”字段映射；没有重新引入旧版默认费率列。
- 首页增加“下载导入模板”，下载文件与后端内置文件保持一致。

### 自填与审核

- 资源端在“资料收集”生成邮箱绑定邀请，可绑定已有译员ID，默认有效14天，可撤销。
- 公开入口 `app.intake_public:app` 只有填写页、邀请上下文和提交接口，不提供后台登录、译员列表、导出或接口文档。
- 译员填写基础资料、语言对、可选报价、能力和多条项目经历；页面提供中英文标签，手机宽度可用。
- 提交后进入 `pending`；资源端可以查看新旧资料、退回补充、拒绝或审核入库。
- 报价必须单独勾选确认；未提供的更新字段保持原值；项目经历仅新增并跳过完全相同记录。
- 同名或同邮箱申请提示候选，需人工选择合并；更名保留旧名称映射。
- 申请版本、邀请写锁、正式档案指纹和数据库事务防止过期差异、并发重复提交及重复审核。
- 令牌只保存 SHA-256 摘要，原令牌放在 URL 片段并通过请求头提交；公开请求体上限128 KiB，每进程每IP每分钟120次。

### 数据清理与备份

用户明确要求清空本地测试数据。已先备份，再清空两个活动 SQLite 文件中的数据行并保留表结构：

- `backend/app.db`：清空前 29 条译员、282 条审计等演示数据；清空后译员、审计、PO、项目、邀请和申请均为 0。
- `data/app.db`：清空前 4 条旧演示译员及关联数据；清空后各表为 0。
- `backend/backups/data-app-pre-clear-20260907_172412.db`：旧库清空前快照，含 4 条记录。
- `backend/backups/pre_intake_20260907_152857.db`：新版迁移前快照，含 29 条记录。
- 清空后的两个活动库均通过 `PRAGMA integrity_check`；旧 Docker 空库另行初始化为最新结构，两库版本均为 `20260907_0009`。
- 修正空库启动自动写入演示数据的旧行为：默认保持空库，只有 `SEED_DEMO_DATA=1` 才生成示例；验收脚本显式开启测试种子。

备份文件不进入部署包，也不提交到 Git。需要恢复时先停止服务，再使用对应快照替换目标数据库，并执行完整性检查。

清理过程中的缺口：第一次用 Linux `/proc` 检查进程，在 macOS 未能停止服务，随后核对进程号并停止。两个 `app.db` 的清空前备份曾发生同名覆盖；保留了旧库的清空前快照，并另命名。29条记录的当前库使用今日15:28预迁移完整快照作为恢复点，不把它称为17:24的精确快照。

## 部署包

已生成 `translator-management-deploy-2026-09-07.zip`。包内包含 Dockerfile、Compose 配置、后端代码、Alembic 迁移、前端页面、模板和运行说明；排除 `.git`、数据库、密钥、日志、备份、测试数据、输出文件和本地依赖。

Docker 启动前必须提供固定的 `JWT_SECRET`、64位十六进制 `AES_KEY` 和持久化 `data/` 目录。容器先执行 `alembic upgrade head`，迁移失败不会启动服务。公开自填服务应单独部署 `app.intake_public:app`，管理服务继续限制在内网；当前没有发布公网地址或发送邀请。
