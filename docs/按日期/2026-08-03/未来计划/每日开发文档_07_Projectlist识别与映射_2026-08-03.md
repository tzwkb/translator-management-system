## 三、识别规则

- 优先匹配标准化名称包含 `Projectlist` 的工作表。
- 未命中时，在各工作表前 10 行搜索必需表头组合。
- 表头至少应包含：指定译员、归属项目或项目名称、目标语言、工作类型、翻译费率、币种、译员 PO 时间。
- 原始列位置不得写死为 A、B、C；按标准化表头映射。
- 空行、合计行和说明行不生成候选 PO。

## 四、首版字段映射

| PO 字段 | Projectlist 来源 |
|---|---|
| `translator_name` | 指定译员 |
| `settlement_month` | 译员PO时间（X月） |
| `project` | 归属项目；缺失时使用项目名称（稿件/LQA批次） |
| `source_lang` | 原语言 |
| `target_lang` | 目标语言 |
| `role` | 工作类型 |
| `rate` | 翻译费率 |
| `currency` | 币种 |
| `word_count` | 按 07-24 已确认的 REP/WWC 口径选择 |
| `remarks` | 批次名称、关联日报内容等可追踪信息 |

“结算PO”字段的实际语义必须在映射注释中固定：若它是状态则转换为 PO 状态；若是编号则映射到 `po_number`，不能同时猜测两种含义。

## 五、实现边界

- 建议把解析函数从 `admin.py` 拆到 `backend/app/po_import.py`。
- 解析函数输入工作簿字节，输出候选行和带原始行号的错误列表。
- 不引入 pandas；继续使用现有 openpyxl。
- 不建设任意模板配置器。
- 测试中的合成工作簿不得包含真实译员个人信息。
