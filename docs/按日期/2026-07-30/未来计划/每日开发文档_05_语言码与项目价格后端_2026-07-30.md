## 三、语言码方案

- 数据库存储稳定规范码，代码本身不随界面语言改变。
- 首版保留现有 109 个选项，增加别名归一化，不在本日大规模重写历史值。
- `ZH-HANS`、`ZH-CN` 等旧值通过显式映射读取和导入。
- 接口返回 `code`、中文名称、英文名称，前端按当前语言选择显示名。

## 四、项目专用价格模型

建议新增 `special_rates`：

| 字段 | 说明 |
|---|---|
| `translator_id` | 译员 |
| `project_experience_id` | 可选，关联具体项目经历 |
| `project_name` | 项目名称快照 |
| `source_lang/target_lang` | 语言对 |
| `rate_type` | `fixed/custom` |
| `task_type` | 翻译、LQA 等标准任务，可空 |
| `custom_task_name` | `custom` 时必填 |
| `amount` | 固定总价或自定义价格 |
| `unit` | `project/task/hour/word/other` |
| `currency` | 币种 |
| `remarks` | 使用范围说明 |

首版不建立版本化通用费率引擎；常规翻译、MTPE、审校、LQA、LQE 仍使用现有语言对费率。

## 五、接口计划

## 七、验收标准

- 旧语言码仍能被读取和匹配。
- 新写入语言码符合统一格式。
- 一口价必须有项目、任务范围、金额和币种。
- “其他”必须有自定义任务名称。
- 金额不能为负；源语言和目标语言不能相同。
- 同一译员可保存多条不同项目、不同任务的专用价格。
