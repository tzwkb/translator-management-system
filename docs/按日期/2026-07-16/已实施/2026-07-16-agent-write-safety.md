# Agent 数据写入安全开发计划

> 文档状态：已实施｜日期：2026-07-16｜说明：计划已完成，验收证据见同目录《验收测试报告_Agent写入安全_2026-07-16.md》。

日期：2026-07-16  
预计工时：5–6 小时

## 一、目标

完善 Agent 向译员管理系统写入费率、PO 和 PO 状态建议时的安全机制，避免消息重复处理、网络重试或连续调用产生重复待审记录。

本轮交付：

- Dry-run：先预览写入内容，不落库。
- 幂等控制：同一来源消息重复提交只处理一次。
- 内容防重：不同消息 ID 但内容相同的未处理建议不重复创建。
- Agent 客户端和 skill 同步支持上述能力。

## 二、范围

涉及接口：

- 费率建议：`POST /api/translators/{id}/rate-changes`
- PO 建议：`POST /api/po`
- PO 状态建议：`PUT /api/po/{id}/status`

不包含：

- 产能等低风险直接写入功能。
- 前端预览弹窗。
- 历史重复数据清理。
- 通用消息队列或跨系统事务。

## 三、技术方案

### 1. Dry-run

Agent 请求携带 `X-Dry-Run: true`。后端完成身份和字段校验后返回规范化预览，不创建待审记录、不写审计日志、不占用幂等键。

### 2. 幂等控制

请求携带 `Idempotency-Key`，建议由“消息来源 + 会话 ID + 消息 ID + 操作类型”组成。

- 同一 Agent、同一幂等键、相同内容：返回原待审记录。
- 同一幂等键、不同内容：返回 HTTP 409。
- 幂等键在记录批准或驳回后仍保持有效。

### 3. 内容防重

后端按操作类型、译员 ID 和规范化业务内容计算 SHA-256 指纹。

- 相同内容已有未处理待审：返回现有记录。
- 原记录已批准或驳回：允许使用新幂等键重新提交。

### 4. 数据结构

数据结构调整：

- `pending_changes.payload_hash`：规范化业务内容指纹。
- 新表 `pending_idempotency`：保存 Agent、幂等键、请求指纹和待审 ID 的绑定关系。
- `pending_changes` 保留首个幂等键镜像，用于兼容已运行的早期版本。

一个待审可绑定多个来源消息键。增加幂等唯一约束和活动待审唯一索引；旧待审在启动升级时回填指纹。本轮沿用现有 `ensure_schema()` 兼容 SQLite，Alembic 迁移不纳入本轮。

## 六、测试场景

1. Dry-run 后待审记录和审计记录数量不变。
2. 同一幂等键和相同内容重复提交，只产生一条待审。
3. 同一幂等键提交不同内容，返回 409。
4. 不同幂等键但内容相同，未处理期间只产生一条待审。
5. 原记录处理后，使用新幂等键可以重新提交。
6. 未携带新请求头的现有调用保持兼容。
7. 费率、PO、PO 状态三个接口行为一致。
8. 并发重复提交只产生一条待审；并发批准只执行一次。
9. PO 批准后，同键重试仍返回原批准结果。

## 七、验收标准

- 三个 Agent 钱相关接口均支持 Dry-run。
- 重复提交不会生成重复待审记录。
- 并发提交和并发审批不会产生重复业务记录或 500。
- 幂等键冲突有明确错误信息。
- Agent 客户端和 skill 已同步更新。
- 后端验收、客户端测试、编译检查和格式检查全部通过。
- 原有费率、PO、待审审批流程无回归。

## 八、风险与边界

- 上游没有稳定消息 ID 时，只能依赖内容指纹防重。
- SQLite 并发能力有限，唯一索引作为最终一致性保护；多人高并发需后续升级数据库。
- 本轮不引入 Alembic，新增字段继续通过现有启动补丁维护。
- 执行自动化测试前需取得明确的“跑”或“go”授权。
