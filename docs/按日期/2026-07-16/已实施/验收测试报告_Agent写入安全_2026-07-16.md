## 三、Agent 关键验收用例

共同前置条件：系统已启动；存在资源端 Agent、资源端编辑账号、测试译员及测试 PO；每轮使用独立临时数据库。

| 编号 | 场景与操作 | 预期结果 | 实测 |
|---|---|---|---|
| AG-01 | 费率建议携带 `X-Dry-Run: true` | 返回规范化预览；不新增待审、审计或幂等记录 | 通过 |
| AG-02 | PO 建议执行 Dry-run | 不新增 PO，不新增待审 | 通过 |
| AG-03 | PO 状态建议执行 Dry-run | 原 PO 状态不变，不新增待审 | 通过 |
| AG-04 | Dry-run 提交非法语言代码 | 返回 HTTP 400 | 通过 |
| AG-05 | Dry-run 提交不存在的译员 | 返回 HTTP 404 | 通过 |
| AG-06 | Dry-run 修改不存在的 PO | 返回 HTTP 404 | 通过 |
| AG-07 | 同一幂等键重复提交相同内容 | 返回原待审 ID；待审记录仅一条 | 通过 |
| AG-08 | 同一幂等键提交大小写、空格不同但业务等价的内容 | 规范化后返回原待审 ID | 通过 |
| AG-09 | 同一幂等键提交不同业务内容 | 返回 HTTP 409，不生成新待审 | 通过 |
| AG-10 | 不同幂等键提交相同活动内容 | 内容防重，返回同一待审 ID | 通过 |
| AG-11 | 原待审已处理后使用新幂等键重提 | 允许创建新待审 | 通过 |
| AG-12 | 已批准 PO 使用原幂等键重试 | 返回原批准结果，不重复创建 PO | 通过 |
| AG-13 | 已批准 PO 使用原幂等键提交不同内容 | 返回 HTTP 409 | 通过 |
| AG-14 | 两个线程以同一键并发提交 | 两次调用成功返回同一待审，仅落一条记录 | 通过 |
| AG-15 | 两个线程以不同键并发提交相同内容 | 内容防重，仅落一条待审 | 通过 |
| AG-16 | 两个线程并发批准同一 PO 待审 | 仅一次批准成功，仅创建一条 PO；无重复写入 | 通过 |
| AG-17 | 旧 SQLite 库启动升级 | 自动补字段、索引和幂等绑定表，旧记录可继续重放校验 | 通过 |
| AG-18 | Agent 客户端提交费率、PO、PO 状态 | 正确传递语言对、`Idempotency-Key` 和 `X-Dry-Run` | 通过 |
| AG-19 | Agent 提交费率建议后待审未处理 | 主表费率保持不变 | 通过 |
| AG-20 | 编辑账号批准或驳回建议 | 批准后业务数据生效；驳回后待审清除；审计记录完整 | 通过 |
