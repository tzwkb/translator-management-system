# Alembic 引入开发文档

> 文档状态：已实施｜更新：2026-07-17｜Alembic 配置、初始迁移、旧库接管、启动调整和测试已完成。交付证据见 `2026-07-17/已实施/`。

## 一、项目目标

为现有 FastAPI、SQLAlchemy、SQLite 项目建立可追踪、可测试、可部署的数据库版本管理机制。

引入后，数据库结构变化由 Alembic 迁移文件统一管理。应用启动不再通过 `create_all()` 和 `ensure_schema()` 静默修改生产数据库。

## 二、当前状态

- 项目使用 SQLAlchemy 定义 12 张业务表。
- 数据库使用 SQLite 单文件存储。
- `backend/app/main.py` 在应用启动时执行 `Base.metadata.create_all(engine)` 和 `ensure_schema()`。
- `ensure_schema()` 同时承担历史字段补充、数据回填、重复数据处理和索引创建。
- 当前数据库没有独立的结构版本号。

## 三、目标架构

### 已有数据库

已有数据库先完成一次历史结构整理，在副本中确认与当前 SQLAlchemy 模型一致，再记录为 Alembic 初始基线。该过程不得重新创建或清空业务表。

### 全新数据库

全新数据库通过 Alembic 初始迁移创建全部业务表、索引、外键和唯一约束，不依赖应用启动时自动建表。

### 后续升级

每次数据库结构变化均生成独立迁移文件。迁移文件与对应模型、业务代码和测试进入同一发布版本。

## 四、技术范围

### 新增内容

| 内容 | 作用 |
|---|---|
| Alembic 配置 | 连接项目数据库和迁移目录 |
| 初始结构迁移 | 从空数据库建立当前完整结构 |
| 迁移版本目录 | 保存后续数据库结构变化 |
| 迁移自动测试 | 验证空库升级、版本一致性和关键索引 |

### 调整内容

| 文件 | 调整方向 |
|---|---|
| `backend/requirements.txt` | 增加受控 Alembic 版本 |
| `backend/app/models.py` | 将手工条件索引纳入模型元数据 |
| `backend/app/main.py` | 停止启动时自动创建和修改数据库结构 |
| `backend/app/db.py` | 将历史整理逻辑限制为首次基线接管用途 |
| `backend/tests/` | 增加迁移测试并调整隔离验收启动方式 |
| `README_ZH.md` | 记录数据库版本管理规则 |

## 五、预计工时

| 工作日 | 工时 | 范围 |
|---|---:|---|
| 第 1 个工作日 | 3–5 小时 | Alembic 配置、模型元数据、初始迁移、空库验证 |
| 第 2 个工作日（可能） | 1–2 小时 | 已有库接管、启动调整、回滚演练 |
| **合计** | **4–7 小时** | 完整迁移体系 |

工时不包含迁移过程中发现历史数据库结构不一致后的专项修复。如果需要修复异常数据，应单独评估并安排工作日。

## 六、全局约束

- 不在真实生产数据库上生成或试跑迁移文件。
- 首次操作真实数据库前必须生成独立备份。
- 备份必须完成完整性检查和恢复演练。
- Alembic 自动生成的迁移必须人工审查。
- 数据库迁移失败时应用不得继续启动。
- 不允许只修改 SQLAlchemy 模型而遗漏迁移文件。
- 不允许手工修改生产数据库后不补充迁移记录。
- `alembic downgrade` 不能替代 SQLite 备份。
- 不为引入 Alembic 顺带重构无关业务代码。

## 七、主要风险

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 现有数据库没有版本记录 | 首次基线可能标记错误 | 先在完整副本验证结构和数据 |
| `ensure_schema()` 包含数据处理 | 简单删除会遗漏历史整理 | 首次接管保留一次性执行能力 |
| SQLite 修改表能力有限 | 复杂迁移可能重建并复制整张表 | 使用批处理迁移并提前检查磁盘空间 |
| 自动生成结果不完整 | 可能遗漏条件索引或数据转换 | 人工审查迁移并进行模型差异检查 |
| 降级迁移删除数据 | 回滚时可能造成二次损失 | 优先恢复部署前备份 |

## 八、回滚原则

### 代码问题且数据库兼容

切回上一应用版本，继续使用当前数据库，不执行数据库降级。

### 结构迁移可安全撤销

停止服务并备份当前数据库，经工程师确认后执行指定降级，再切回旧应用版本。

### 数据被删除、转换或损坏

停止服务，保留故障数据库副本，恢复部署前 SQLite 备份，再切回旧应用版本。恢复前必须确认备份之后新增数据的处理方式。

## 九、验收标准

- 空白数据库能够通过初始迁移创建 12 张业务表。
- 已有数据库能够安全记录初始版本，业务数据不丢失。
- 数据库结构与 SQLAlchemy 模型之间没有未记录差异。
- 两个待审核条件唯一索引被纳入正式模型和迁移。
- 应用导入和启动不再自动创建或修改数据库结构。
- SQLite 备份通过完整性检查并完成恢复演练。
- 现有后端、前端、幂等、数据质量和验收测试全部通过。
