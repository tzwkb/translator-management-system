# 译员管理系统 Docker 云部署开发日志

> 文档状态：待实施｜日期：2026-07-16｜目标：5 小时内完成 Docker 打包并上线可访问的 Demo。

**当前阶段：** Demo 部署  
**目标：** 将现有 FastAPI、单页前端和 SQLite 数据库打包为 Docker 镜像，部署到云平台，完成核心功能演示。

## 一、当前状态

- 项目已有 `Dockerfile` 和 `docker-compose.yml`，具备基础容器化条件。
- 前端由 FastAPI 同源提供，无需单独部署静态站点。
- SQLite 继续作为 Demo 数据库，使用云平台持久磁盘或挂载目录保存。
- Alembic 本地迁移体系已于 2026-07-17 完成，初始版本为 `20260717_0001`，需要接入镜像和容器启动流程。
- 当前登录机制为免密码角色 token，仅适合受控 Demo，不作为正式公网生产方案。
- 当前工作区存在未提交修改，打包前需要确认本次 Demo 使用的代码版本。

## 二、本次范围

本次按 **5 小时以内**完成，交付范围如下：

1. 确认 Demo 发布代码和必要环境变量。
2. 完成 Docker 镜像打包，并接入 Alembic 数据库迁移。
3. 在本地启动容器，验证首页、API 和数据持久化。
4. 将镜像部署到支持 Docker 的云平台，获得可访问的 HTTPS Demo 地址。
5. 对登录、译员、费率、PO 和审核等核心流程执行冒烟测试。

本次不包含正式生产级账号体系、安全审计、自动备份恢复、完整监控告警、多实例部署、PostgreSQL 迁移、自定义域名及长期运维交接。以上内容在 Demo 验收后另行安排。

## 四、5 小时实施安排

### 第 1 阶段：发布确认与部署准备（0:00–0:30）

- [ ] 确认本次 Demo 使用的代码版本和未提交修改。
- [ ] 备份当前 SQLite 数据库，避免部署操作影响现有数据。
- [ ] 整理 `JWT_SECRET`、`AES_KEY`、数据库路径等必要环境变量。
- [ ] 确认云平台账号、区域、部署方式和可用资源。

**完成标准：** 发布内容、配置项和部署目标明确，可以开始打包。

### 第 2 阶段：Docker 打包与启动链路（0:30–2:00）

- [ ] 确认应用依赖、前端资源和启动命令均已写入镜像。
- [ ] 将 `backend/alembic.ini`、`backend/migrations/` 和版本文件打包进镜像。
- [ ] 在 FastAPI 启动前执行 `alembic upgrade head`；迁移失败时容器退出。
- [ ] 配置 SQLite 数据目录和必要配置目录为外部挂载路径。
- [ ] 构建带明确版本标签的 Docker 镜像。

**完成标准：** 镜像构建成功；容器能够执行迁移并启动应用。

### 第 3 阶段：本地容器验证（2:00–3:00）

- [ ] 使用空数据目录启动容器，确认 Alembic 能创建数据库结构。
- [ ] 验证首页、健康检查或基础 API 可以访问。
- [ ] 创建少量 Demo 数据，重启容器后确认数据仍然存在。
- [ ] 检查日志，确认没有迁移失败、启动异常或持续报错。
- [ ] 修复阻塞部署的 Docker 配置问题并重新构建。

**完成标准：** 本地容器可稳定启动，页面和 API 可访问，重启后数据不丢失。

### 第 4 阶段：云端 Demo 部署（3:00–4:30）

- [ ] 在云平台创建单实例 Docker 服务。
- [ ] 配置环境变量、SQLite 持久目录和应用端口。
- [ ] 上传或构建镜像，启动云端容器。
- [ ] 使用平台默认域名和 HTTPS，不配置自定义域名。
- [ ] 检查云端日志、容器状态和外部访问结果。

**完成标准：** 获得可访问的 HTTPS Demo 地址；容器状态正常；重新启动后 Demo 数据保留。

## 五、Demo 验收标准

- Docker 镜像可以成功构建并带有明确版本标签。
- 新容器启动时能够执行 Alembic 迁移，迁移失败时不会继续启动应用。
- 云端 HTTPS 地址可以正常打开首页并访问基础 API。
- 译员、费率、PO 和审核等核心演示流程至少完成一轮冒烟测试。
- 容器重启后 SQLite 数据仍然存在。
- `JWT_SECRET` 和 `AES_KEY` 通过云平台环境变量提供，不写入镜像或仓库。
- 已明确记录 Demo 的安全限制和后续生产化事项。
